一、直接回答两个问题

① MasterGo 现在还会不会出错？会 —— 但错在取字段，不在数据。
MasterGo 的 TEXT 节点同时带 fill 与 textColor[] 两套颜色。fill 是背景、textColor 才是文字色——这不是推测，是 MasterGo 自己的代码生成器给出的：同一节点它输出 background-color: #FEFEFE; color: #FEFEFE，前者来自 fill，后者来自 textColor。按 _token || fill 取名字，等于把背景色当文字色用，Button 页 310 个文字节点里有 254 个两处绑定不同、193 个在夜间会取到错色。
② Figma 能不能读全？能读到「绑定了哪个变量」，读不到「变量叫什么」。
Figma 的 boundVariables 精确到每条 paint、每个属性：全文件 31,301 条 SOLID 引用里 21,222 条带绑定（67.8%），节点级与 paint 级两处 alias 0 处冲突。但变量名接口 /variables/local 返回 403——当前令牌缺 file_variables:read（企业版权限），所以只能拿到 VariableID:3:30 这类内部 ID，拿不到 Primitive/Neutral/70。

五、MasterGo 到底哪里会错官方代码生成器给出的证据

关键一步不是猜，而是让 MasterGo 自己的生成器说话。对同一个文字节点调用 getComponentGenerator，它给出的 cssCode 是：

Lg-Full  // 38623:90228，画布上的尺寸标注
{"cssCode":"position:absolute;...background-color: #0D0D0D;color: #FEFEFE;font-size:14px;..."}

确定     // 36289:34080，Solid 按钮文案
{"cssCode":"position:absolute;...background-color: #FEFEFE;color: #FEFEFE;font-size:16px;..."}

对照 DSL 原始字段即可确认映射关系：

节点fill（→ background-color）textColor（→ color）
38623:90228
Lg-Full		#0D0D0D
token: Text/Primary		#FEFEFE
token: Primitive/Neutral/0
36289:34080
确定		#FEFEFE
token: Primitive/Neutral/0		#FEFEFE
token: Text/Inverse/Primary

所以结论很硬：fill 是背景，textColor 是文字色。我在 10:20 那份《变量名获取方式》里写的 token = node._token || styles[node.fill]?.token 对文字节点是错的，会把背景变量名当成文字变量名输出——这正是前端复现里「Solid 按钮夜间白字配近白底」的成因。

为什么不容易发现

Light 模式下两者经常同值。Solid 按钮文案：Primitive/Neutral/0 与 Text/Inverse/Primary 都是 #FEFEFE；Outline 按钮文案：Primitive/Neutral/70 与 Text/Primary 都是 #0D0D0D。截图、肉眼、甚至「值一致性自检」全部通过，只有切到 Dark 才暴露：

按钮类型fill 的 Dark 值textColor 的 Dark 值按钮底色（Dark）用 fill 的后果
Solid#FEFEFE#0D0D0D#F9F9F9白字压近白底
Outline#0D0D0D#FEFEFErgba(13,13,13,.95)黑字压近黑底

七、这次新查出来的四个问题

1. 图标类变量命名两端不一致

Figma 表里是 Icon/Transparent/Default 这种「层级式」，MasterGo 里是 Icon/Transparent-default 这种「连字符式」。值全对，名字对不上，做映射表时必须额外写一层转换规则。

2. Figma 自己的图标命名有内部不一致

同一组灰色图标，一条叫 Gray40/Default，另一条叫 Gray/40/Hover——少了斜杠。这类笔误在人工核对时看不见，但做 token 匹配会直接失配。MasterGo 侧已统一为 Icon/Gray-40-default。

3. 508 个文字节点没绑变量

文件级 TEXT 8,963 个，其中 508 个（5.7%）填的是手写 #0d0d0d。这些在 Dark 模式下不会变色。主要集中在画布说明文字与部分图标页标注，不进产品代码，但需要标明。

4. Figma 的 Dark 覆盖只存在于演示块

全文件 21,222 条绑定引用里，落在 Dark 模式的只有 130 条（0.6%），全部集中在少数「场景实际运用」预览框。想核对全量 Dark 值，只能切模式重新拉一遍画布，或走变量表——而变量表接口正好没权限。这是 Figma 侧目前最大的盲区。

八、结论与下一步

  • MasterGo 的错能修。规则只有一条：TEXT 取 textColor[]，其余取 fill；两者都不能命中就报 MISS，不许回落到色值。脚本已加 role: render/decoy 字段拦截。
  • Figma 补名字只差一个权限。生成一个新 PAT 时勾上 file_variables:read（需企业版席位），/variables/local 立刻可用，VariableID 就能换成真名。
  • 两端语义层已经对齐。36 条语义变量双模式零差异，说明两份文件是同源维护的，问题都在取数环节，不在规范本身。
  • 反查这条路彻底放弃。Figma 0/289、MasterGo 19/96，两边的结论一致：颜色值是一对多的，只有绑定字段是一对一的。
