R1三个问题的结论

问题结论
MasterGo 能否解析 Light / Dark？能，直连 变量表一次取全 171 变量，颜色变量带双模式值
Figma 能否解析 Light / Dark？能，但绕路 节点带变量绑定与模式 ID，同一变量在两画框解析出两套值
两端值是否一致？完全一致 逐 token 比对无差异，已落成带一键切换的交互组件
一句话：模式两端都能被机器读到，值也对得上。差别不在「能不能读」，而在通道成本、数据形态（有无变量 ID 绑定）、能否回写画布。

组件变体data-variant-* 属性，实例完好组件定义 295 个、变体名可解析；但示例帧内实例已被拍平为普通 frame（全文件 0 个 INSTANCE），页面级拿不到 componentProperties
代码生成内置多框架（客户端 MCP 导出为固定色值，不带 token 名）无内置
MCP 通道差异两套：Magic MCP 的间距（报 31 实为 40）、圆角、深色值有误；客户端 MCP 数据准确一条（Figma MCP / REST）
回写画布支持只读
国内可用性直连稳定需代理 / WAF 拦

MasterGo

  • 接入零成本；语义变量可直接生成 CSS 变量体系
  • 可回写，AI 能反向改稿、批量建组件
  • 节点不带变量 ID，易产出硬编码
  • 输出是拍平 HTML/CSS，大页面需分块读

Figma

  • 数据模型最接近代码，token 链路可追溯
  • 变体命名规范，直映 props；生态成熟
  • 变量接口锁企业版；只读；国内网络不稳
  • 变体数量易爆炸，命名不收敛会拖累生成

R7给规范整理的 5 条结论

  • 变量分两层：Primitive 存原始色阶，Semantic 存用途（Button/Solid/Bg/Hover）。AI 只能靠 Semantic 层产出组件 token。
  • 变体锁死四轴：Variant × Size × State × Breakpoint，禁止 Lg-1/Lg-Regular 这类临时档。
  • 层名语义化：按钮内部叫 label / icon，别留「容器 1411」。
  • 状态写成矩阵：显式列出五种状态取值，而不是只画五张贴图。
  • 附 token ↔ 值 对照表：绕开 Figma 企业版权限，让 AI 同时拿到名字和值。
